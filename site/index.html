pg_sandbox

disposable PostgreSQL, on demand

A command-line tool that provisions, manages, and tears down local PostgreSQL sandbox instances for development, testing, and bug reproduction. It ships as a single static binary with no runtime dependencies beyond the PostgreSQL binaries you point it at.

Install See the demo walkthrough View on GitHub
pg_sandbox — bash
# point at an existing PostgreSQL install, then spin one up
$ export PGS_BIN_DIR=/opt/postgresql/18.4
$ pg_sandbox deploy -s pg18
$ pg_sandbox use -s pg18            # open psql
$ pg_sandbox run -s pg18 -- pgbench -i
$ pg_sandbox destroy -s pg18 --force
What it does

A lifecycle orchestrator for local PostgreSQL

Not a database driver, server, or HA system — a tool to stand instances up and tear them down cleanly. Every invocation is a short-lived process; there is no daemon.

One-command instances

Stand up an isolated PostgreSQL instance with a single deploy. Ports are auto-allocated; connect with use or run any utility with run.

Replicated topologies

Stand up physical streaming replication and logical pub/sub with --replicate-from, publish, and subscribe.

Managed clusters

Provision a primary + N standbys (or publisher + N subscribers) in one cluster deploy, with shared manifest metadata and a consolidated status view.

Live state reporting

Ask any sandbox whether it's running, primary or standby, its replication lag and subscriptions — as text or --json.

Host-wide overview

global_status lists every sandbox on the machine at a glance, in text or JSON for piping into jq.

pg_gather reports

Generate a pg_gather HTML report from a captured out.txt in a throwaway sandbox that's cleaned up automatically on success.

Build from source

Compile any PostgreSQL version with build <version> — optional --with-icu / --with-openssl and debug builds via PGS_BUILD_DEBUG.

Layered configuration

Resolve every value through a documented chain — CLI flag > PGS_* env var > sandbox config > global config > default. Inspect exactly where each came from with config show.

1Download & install

install the Linux x86_64 binary into /usr/local/binpre-built
curl -L -o /usr/local/bin/pg_sandbox \
  https://github.com/guriandoro/postgresql_sandbox/releases/latest/download/pg_sandbox-linux-amd64
chmod +x /usr/local/bin/pg_sandbox

Pre-built binaries have no Go requirement. CGO_ENABLED=0 on the cross-compile path means the Linux artifacts have no glibc dependency and run on any reasonably-recent kernel.

2Build from source

requires Go 1.22 or newersource
# local-arch binary into ./bin/pg_sandbox
make build

# all four release binaries into ./bin/
make build-all

# or, without GNU make:
./scripts/build.sh

Binaries are stripped (-ldflags="-s -w") and stamped with the current version + commit — pg_sandbox --version shows both.

Requirements

What you need on the machine

pg_sandbox does not bundle PostgreSQL — it points at an existing install and trusts that install's own version semantics.

PostgreSQL binaries

initdb, pg_ctl, psql, pg_basebackup, pg_dump reachable on disk — pointed at via --bin-dir or PGS_BIN_DIR.

macOS or Linux

Targets amd64 and arm64. Windows is not supported.

Go 1.22+

Only for building from source — pre-built release binaries carry no Go requirement.

Quick start

End-to-end recipes

Each recipe assumes you've pointed at an install root once per shell session: export PGS_BIN_DIR=/opt/postgresql/18.4. A bare -s <name> resolves under the sandbox root, so it names the same sandbox from any directory.

A single sandbox

deploy · connect · run · tear down

# deploy a standalone instance
pg_sandbox deploy -s pg18

# connect with psql
pg_sandbox use -s pg18

# run any utility (auto-injected flags)
pg_sandbox run -s pg18 -- pgbench -i

# stop and tear down
pg_sandbox destroy -s pg18 --force

Physical streaming replication

primary + async standby

# primary
pg_sandbox deploy -s primary

# async standby attached to it
pg_sandbox deploy -s standby1 \
    --replicate-from primary \
    --slot primary_standby1_slot

# promote standby1 if primary dies
pg_sandbox promote -s standby1

Logical pub/sub

publisher + subscriber

# publisher
pg_sandbox deploy -s pub
pg_sandbox publish -s pub \
    --pub-name my_pub --all-tables

# subscriber (deployed already subscribed)
pg_sandbox deploy -s sub \
    --subscribe-to pub \
    --pub-name my_pub --copy-schema

A managed cluster

1 primary + 2 standbys

# deploy the whole cluster at once
pg_sandbox cluster deploy -s mycluster \
    -N 2 --sync-count 1

# consolidated status
pg_sandbox cluster status -s mycluster

# tear down everything in one shot
pg_sandbox cluster destroy -s mycluster --force
Reference

The command set

Run pg_sandbox help <command> (or pg_sandbox <command> --help) for full usage, flags, and examples on any single command.

Lifecycle

  • deploy — create a new sandbox
  • destroy — tear down a sandbox
  • start / stop / restart — control PostgreSQL
  • status — running state + replication info
  • use — open psql against a sandbox
  • run <bin> — run any PG utility
  • promote — standby → standalone primary

Configuration

  • config show — effective config + source
  • config get <KEY> — read one value
  • config set KEY=VAL — mutate atomically
  • config validate — check the config
  • config migrate — convert legacy .env

Replication

  • publish — create a publication
  • subscribe — create a subscription

Cluster orchestration

  • cluster deploy — primary + N standbys
  • cluster status — consolidated view
  • cluster destroy — tear the cluster down

Cross-host & reporting

  • global_status — list every sandbox
  • report --input — pg_gather HTML report

Source build & maintenance

  • build <version> — compile PG from source
  • cleanup-install-versions — prune unused installs
  • help [<command>] — built-in help
